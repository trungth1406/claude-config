# Ticket Gate — /to-tickets before any work

Never begin implementation work unless /to-tickets has created the task's
tickets first. No tickets, no work — however small the task.

- Before to-tickets (per The Flow): grill-me for clarity, then the design
  skills (codebase-design, domain-modeling, design-an-interface, language
  best-practice skill), then to-spec. Tickets are the output of that chain,
  never a shortcut around it.
- After to-tickets: /implement fires only on an existing ticket, followed by
  the mandatory review gate (see review-qa-gate.md).

Full before/after doctrine: ~/.claude/CLAUDE.md — The Flow.
